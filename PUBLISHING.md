# Как публикуются обновления оболочки

Обновляется через этот механизм **только сама Electron-оболочка** (окно, шапка,
печать, настройки). Сайт кабинета обновляется сам собой, этого файла не
касается.

## Разовая настройка (один раз)

1. Создать **публичный** репозиторий на GitHub: `ahilespelid/litewms_electron`
   (имя владельца и репозитория должны совпадать с `build.publish` в
   `package.json` — если владелец другой, поправить оба места).
2. Запушить в него **только содержимое папки `desktop/`** этого репозитория —
   отдельный git-репозиторий, не связанный с `litewms`.
3. Сделать личный токен GitHub (Settings → Developer settings → Personal
   access tokens) с правом `repo` (для приватного) или `public_repo` (для
   публичного) — только на запись релизов. Токен нужен один раз, для машины,
   с которой публикуют обновления, в переменной окружения `GH_TOKEN`. Внутрь
   собранного приложения он не попадает.

## Каждый раз, когда меняется код оболочки

```bash
cd desktop
GH_TOKEN=ваш_токен npm run release
```

Команда сама:
- соберёт `LiteWMS-Desktop-Setup.exe`;
- посчитает контрольную сумму и сформирует `latest.yml`;
- создаст релиз в GitHub и прикрепит к нему оба файла.

**Обязательно поднять `version` в `package.json` перед каждым релизом**
(например `0.2.0` → `0.3.0`). Если версия не изменится, установленные у
клиентов приложения не увидят обновление — `electron-updater` сравнивает
номера версий, а не даты.

## Что видят клиенты

Через ~4 секунды после запуска и затем каждые 2 часа приложение тихо
проверяет `github.com/ahilespelid/litewms_electron/releases/latest`. Если
версия новее — в шапке рядом с шестерёнкой появляется кнопка:

1. «Обновление N.N.N — скачать» → клик скачивает в фоне;
2. «Скачивание… NN%»;
3. «Перезапустить и установить» → клик тихо ставит новую версию и
   перезапускает приложение.

Ничего скачивать вручную и вводить не нужно.
